# 开始这里

这不是一页“先背目录名”的导览，而是一页用来判断下一步该去哪里的入口。

这个站点要回答的是一个更大的问题：

如何把 AI Code 的需求收口、技术取舍、项目架构、开发规划、实施验证和工作系统接入一起设计成长期能力。

## 先判断你现在缺哪一类信息

### 我还没把问题说清楚

先去 [流程地图](/docs/start/journey-map)。

这一步优先解决“我到底处在哪一环”，不急着谈具体产品或框架。

### 我已经知道问题，但不知道该补哪类长期知识

先去 [知识方向总表](/docs/start/taxonomy)。

这一步优先解决“这件事更像开发范式、工作流、技术选型、治理、架构还是生态集成”。

### 我只想找可直接消费的材料

先去 [资源中心](/docs/tools/resources)。

这一步只负责视频和课程，不承担长期知识骨架。

### 我已经知道方向，但想选阅读形态

先去 [内容索引](/docs/content-index)。

这一步只负责告诉你该读对比、Playbook 还是 Insight。

### 我已经在真实工作系统里落地 AI Code

可以直接去 [生态与集成](/docs/ecosystem)。

这一步优先解决 GitHub、Jira、CI、PR 和组织接入闭环，而不是继续停留在单点工具体验。

## 推荐的最短进入顺序

1. [流程地图](/docs/start/journey-map)
2. [知识方向总表](/docs/start/taxonomy)
3. [学习路径](/docs/start/learning-paths)
4. 进入对应方向或覆盖层

## 如果你只有 20 分钟

1. 前 5 分钟：看 [流程地图](/docs/start/journey-map)，确定当前阶段。
2. 接下来 5 分钟：看 [知识方向总表](/docs/start/taxonomy)，确定主方向。
3. 接下来 5 分钟：看 [学习路径](/docs/start/learning-paths)，确定默认顺序。
4. 最后 5 分钟：进入对应方向首页或资源中心。
