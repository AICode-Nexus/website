# 开始这里

这个站点不是产品新闻堆，也不是一组零散教程。它服务一个更具体的目标：帮助个人工程师把 AI coding 从“偶尔用一下”变成“每天都能稳定交付”。

## 这一类内容解决什么问题

- 我应该先选哪类平台作为主入口。
- 我今天要修 bug、做重构、补测试，应该走哪条 workflow。
- 我该如何区分短期热点和长期值得沉淀的方法。
- 我什么时候该继续深挖，什么时候该停止试工具、开始固定栈。

## 谁应该先读

- 想搭第一套 AI coding 工作流的个人工程师
- 已经在试 Copilot、Codex、Cursor 等工具，但没有形成稳定产出的工程师
- 想从“偶尔问一下 AI”升级到“日常研发流程都能用”的读者

## 先建立三层认知

### 第一层：主平台

先选一个主平台，而不是同时长期试五个工具。主平台决定你的默认入口、上下文记忆、Agent 执行方式和 review 回路。

先读：

- [工具选择地图](/docs/tool-selection)
- [GitHub Copilot、VS Code Agent 与 OpenAI Codex 怎么选](/docs/comparisons/github-copilot-vs-vscode-agent-vs-openai-codex)

### 第二层：任务工作流

真正决定产出的不是“会不会提问”，而是你有没有把高频任务拆成稳定流程。第一阶段只要先掌握三条：bugfix、refactor、test。

先读：

- [Prompt Contracts](/docs/prompting-workflows/prompt-contracts)
- [Bugfix / Refactor / Test 工作流](/docs/prompting-workflows/bugfix-refactor-test-workflows)
- [7 天上手路线](/docs/playbooks/first-7-days-ai-coding)

### 第三层：趋势判断

不是每条发布都值得追。你需要一套方法，把每日变化沉淀成长期判断。

先读：

- [2026 年 3 月 AI Coding 的四个主线变化](/docs/insights/agentic-coding-patterns)
- [Daily Brief](/blog)

## 如果你只有 90 分钟

### 前 20 分钟

- 读 [工具选择地图](/docs/tool-selection)
- 确认自己属于哪一类入口：GitHub-first、编辑器控制面、异步长任务、开放式 IDE

### 接下来 25 分钟

- 读 [GitHub Copilot、VS Code Agent 与 OpenAI Codex 怎么选](/docs/comparisons/github-copilot-vs-vscode-agent-vs-openai-codex)
- 先选一个主平台，再选一个备用入口

### 接下来 25 分钟

- 读 [7 天上手路线](/docs/playbooks/first-7-days-ai-coding)
- 把 Day 1 到 Day 3 的动作写进你的本周任务里

### 最后 20 分钟

- 读 [Bugfix / Refactor / Test 工作流](/docs/prompting-workflows/bugfix-refactor-test-workflows)
- 选一个最小 bugfix 任务，准备当天就试一次

## 常见误区

- 一开始就比较所有产品名，而不是先比较入口类型
- 只追模型版本，不追上下文、执行和 review 成本
- 还没建立稳定 workflow，就开始追多 Agent
- 没有记录返工、review 修补量和失败模式
