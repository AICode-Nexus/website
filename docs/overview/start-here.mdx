# 开始这里

这个站点现在不再只服务“个人工程师如何起步”，而是要帮助团队与平台负责人回答一个更大的问题：

如何把 AI 开发方式、工作流、工具、规范和架构一起设计成长期能力。

## 先建立 5 层认知

### 1. AI 开发方式

先决定默认入口与人机分工。

先读：

- [AI 开发方式](/docs/development-modes)
- [AI 开发方式总览](/docs/development-modes-landscape)

### 2. AI 工作流

把需求到 PR 的交付链写清。

先读：

- [AI 工作流](/docs/workflows)
- [主流 AI Coding 工作流](/docs/workflows/mainstream-ai-coding-workflows)
- [AI 工作流实操手册](/docs/playbooks/workflow-playbook)

### 3. AI 编程工具

再比较平台、终端 agent、AI IDE 与开放式入口。

先读：

- [AI 编程工具](/docs/tools)
- [工具选择地图](/docs/tool-selection)

### 4. AI 规范

让不同入口共享同一套规则、权限、验证和评估标准。

先读：

- [AI 规范](/docs/standards)
- [仓库规则文件体系](/docs/repo-instruction-files)

### 5. AI 架构

最后把目录、上下文、worktree 和 MCP 拓扑固定下来。

先读：

- [AI 架构](/docs/architecture)
- [MCP 与工具拓扑](/docs/mcp-tool-topology)
