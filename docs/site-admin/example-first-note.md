# 示例：第一篇知识条目

## 背景

这是站点维护示例，用来说明知识条目应该如何组织结构，避免把临时笔记、脑暴提纲或会议记录直接当成已发布文档。

## 适用场景

- 把临时研究整理成长期 docs
- 把 Daily Brief 主题回流成专题文档
- 把个人笔记改写成团队可复用知识

## 推荐结构

- 背景或适用场景
- 结论先行
- 核心概念或核心做法
- 推荐步骤
- 风险与边界
- 延伸阅读

## 推荐做法

1. 先把草稿写在 `drafts/notes/`
2. 确认内容归属到哪个知识方向、流程阶段或内容形态
3. 用正式结构改写，而不是直接复制草稿
4. 补齐 frontmatter、内部链接和复核信息

## 风险与边界

- 不要把未验证的结论直接发布
- 不要把临时草稿和正式 docs 混在同一目录
- 不要缺少“风险与边界”或“下一步建议”
