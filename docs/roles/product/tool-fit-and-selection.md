# 工具匹配与选型

产品任务最重要的不是“工具谁更强”，而是任务现在更像需求澄清、原型核对、技术调研还是交付跟踪。

| 任务形状 | 更适合的入口 | 为什么 |
| --- | --- | --- |
| 需求分析、PRD 起草 | 更擅长长文档和结构化输出的入口 | 需要稳定章节和依赖表达 |
| 原型或流程验证 | 浏览器或设计上下文能力 | 需要看到真实界面 |
| 技术可行性调研 | 终端或官方文档检索能力 | 需要可信资料和 repo 事实 |
| 交付跟踪与 issue 收口 | 平台型入口 | 适合衔接任务与 review 系统 |

## 一个实用顺序

1. 先定任务形状。
2. 再选入口。
3. 最后补 rules、skills 和验收模板。

## 常见误选

- 需求还没澄清，就直接开始写 PRD 全文。
- 需要看真实流程时，却不打开原型或浏览器上下文。
- 需要技术调研时，只凭旧认知判断复杂度和风险。

## 产品训练建议

最实用的训练方式是把每次产品任务都标成“需求澄清 / 原型验证 / 技术调研 / 交付跟踪”中的一种，再强制要求先写为什么选这个入口。几轮之后，团队会自然形成更稳定的工具选择习惯。
