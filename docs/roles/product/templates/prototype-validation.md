# 原型验证模板

```md
# {原型 / 方案名}

## 1. 验证目标
- 想验证什么
- 如果验证失败，意味着什么

## 2. 验证对象
- 页面 / 流程 / 功能节点
- 使用的原型或 demo 链接

## 3. 核心假设
- 用户是否能理解
- 流程是否走得通
- 技术约束是否允许

## 4. 验证方式
- 走查 / 内部试用 / 小范围用户验证 / 技术 spike
- 参与角色
- 时间窗口

## 5. 成功判定
- 通过标准
- 不通过标准
- 需要补充的证据

## 6. 观察记录
- 正常路径
- 卡点
- 反例

## 7. 结论
- 继续推进 / 调整后再试 / 暂停
- 下一步动作
```

## 使用提醒

- 不要把“做了一个 demo”当成验证完成，必须写清成功判定。
- 观察记录要区分主路径和失败路径，便于后续写验收。
