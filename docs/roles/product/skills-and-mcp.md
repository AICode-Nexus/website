# Skills 与 MCP

产品类任务经常跨文档、跨角色、跨验证方式，所以更需要先选方法，再拿上下文。

## 高价值能力映射

| 任务 | 优先 skill / MCP | 为什么 |
| --- | --- | --- |
| 需求澄清与设计前置 | `brainstorming`、`writing-plans` | 先把问题和方案拆清 |
| PRD 或 spec 产出 | `bmad`、`adr-writer` | 适合结构化文档输出 |
| 竞品或最新 API 调研 | Context7 / 官方文档 | 需要可信最新资料 |
| 原型或流程核对 | 浏览器 / 设计上下文能力 | 需要真实界面与流程证据 |

## 产品任务常见误用

- 不做需求澄清，直接生成 PRD。
- 不查最新官方文档，就把技术约束写进需求。
- 原型讨论不看真实界面，只在文本层抽象。
