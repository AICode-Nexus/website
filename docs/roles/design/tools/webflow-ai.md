# Webflow AI

Webflow AI 的定位更偏“让站点继续生产”，而不是只帮你起一版视觉草稿。按官方当前帮助文档，`AI site builder` 可以从 prompt 生成多页站点结构、主题和样式页，后面还能继续生成页面、区块、文案和 CMS 条目。

## 它最适合什么任务

| 任务 | 适合程度 | 原因 |
| --- | --- | --- |
| 多页营销站或内容站起稿 | 很高 | 直接生成站点结构与主题 |
| 站点继续生产与内容维护 | 高 | 后续还可生页、生成区块、文案、CMS |
| 设计到上线的一体化衔接 | 高 | 不是停在原型，而是继续往可用站点走 |
| 复杂产品界面或后台系统 | 低 | 核心还是 website workflow |

## 它最值得注意的地方

Webflow 当前官方文档里有几个信息很关键：

- AI site builder 只能用于“新建站点”或“继续编辑 AI 生成的站点”
- 它会根据 prompt 生成完整的多页结构、内容和主题
- 会自动生成一个 `Style guide` 页面，集中管理颜色、字体、cards、spacing、gradients 等
- 生成后的站点使用 `Flowkit CSS Framework`
- 后续还能继续生成页面、section、copy 和 CMS items

这说明它不是“出图后就结束”，而是给你一个可以继续运营的网站骨架。

## 实战案例

### 案例：设计师为新产品上线官网

1. 输入产品定位、目标用户、页面目标，让 Webflow AI 生成首页、产品页、关于页、联系页等基础结构。
2. 在站点结构层先调整 page 和 section 顺序，避免一开始就陷入细节。
3. 进入自动生成的 `Style guide` 页面，统一主题色、字体、按钮和卡片规则。
4. 再用 AI 去补新页面、生成 section、改写文案或补 CMS 条目。
5. 最终再做上线前校对，而不是把所有站点内容重新搬一次。

对内容团队和增长团队来说，这条路径很有吸引力，因为它把设计和后续站点运营接得很近。

## 什么时候优先选它

- 你做的是官网、专题站、内容站，而不是产品主界面。
- 你希望设计师不只给稿，还能直接把站点生产推进到更后面。
- 你需要 style guide 和站点结构同时成型，而不是只要一个视觉草图。

## 边界与注意事项

- Webflow 官方明确写了限制：AI site builder 不能直接套在一个原本不是 AI 生成的旧站上。
- 官方也写明：用 AI site builder 生成的站点不能用于分享 `Libraries`。
- 如果你先要和团队做 sitemap、wireframe 审批，[Relume](/docs/roles/design/tools/relume) 往往更适合做前一步。
- 如果你想让设计师自己直接发品牌站，[Framer](/docs/roles/design/tools/framer) 也是强竞争选项。
