# Relume

Relume 的价值不在于“帮你随便生成一个网页”，而在于它把网站项目里最容易拖慢沟通的三步拆出来了：`Sitemap`、`Wireframe`、`Style Guide`。这对 agency、增长团队、品牌站项目尤其有用。

## 它最适合什么任务

| 任务 | 适合程度 | 原因 |
| --- | --- | --- |
| 营销站和品牌站信息架构 | 很高 | 先 sitemap 再 wireframe，审批更快 |
| 网站概念和首轮客户提案 | 很高 | 更适合快速出结构和方向 |
| 连接 Figma / Webflow / React | 高 | 官方明确提供导出路径 |
| 复杂产品工作台或后台系统 | 低到中 | 重心仍是 marketing website |

## 它的 AI 工作流为什么实用

Relume 当前官方主页把整个链路写得很清楚：

1. 用 AI 先生成 `Sitemap`
2. 一键把 sitemap 变成 `Wireframe`
3. 再进入 `Style Guide`
4. 然后导出到 `Figma / Webflow / React`

这和很多“直接整页生成”的工具不同。它更重视项目前期的结构确认和审批效率，所以很适合接客户、对齐内容团队或让非设计同事先参与。

## 实战案例

### 案例：SaaS 官网改版

1. 团队先输入产品定位、目标用户、核心价值和内容模块，用 `Sitemap` 拉出站点结构。
2. 和产品、市场、销售一起确认页面数、区块顺序和信息层级，减少 scope creep。
3. 一键生成 `Wireframe`，先拿到可讨论的页面骨架和区块文案。
4. 用 `Style Guide Builder` 形成第一版视觉方向，做客户或内部审批。
5. 根据实际团队实现方式，把结果导去 Figma、Webflow 或 React。

对很多网站项目来说，这比直接争论“hero 该不该有插画”更高效，因为先把结构讲清楚了。

## 它为什么适合设计师

- 先定结构，再谈视觉，减少来回返工。
- 更适合和客户、市场、内容团队一起评审。
- 官方组件库明确支持 Figma、Webflow、React 三个出口，降低后续重做成本。

如果你经常做 landing page、官网改版、产品官网或内容型站点，这个特点非常关键。

## 边界与注意事项

- Relume 的强项是 marketing website，不是复杂业务后台。
- 它很适合作为前置结构工具，但不是所有团队最后都会把它当最终设计源文件。
- 如果项目最后要进入严格的设计系统和设计到代码交付，通常还要继续用 [Figma](/docs/roles/design/tools/figma) 或 [Webflow AI](/docs/roles/design/tools/webflow-ai) 接下一段。
