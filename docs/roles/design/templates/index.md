# 设计训练包模板

设计任务最怕“图给了，但约束没给”。把 handoff、状态合同、token 约束和原型验证写成固定模板后，设计稿、组件和前端交付之间才不容易断层。

![设计训练包图板](/img/roles/design/design-training-pack-board.svg)

## 先复制哪份

| 场景 | 先复制什么 |
| --- | --- |
| 需要把 Figma 节点、页面和限制交给开发 | [Figma Handoff 包模板](/docs/roles/design/templates/figma-handoff-pack) |
| 需要固定组件状态、变体和交互边界 | [组件状态合同模板](/docs/roles/design/templates/component-state-contract) |
| 需要整理 token、命名和可访问性约束 | [Token 与约束模板](/docs/roles/design/templates/tokens-and-constraints) |
| 需要验证原型、交互和还原结果 | [原型验证与证据模板](/docs/roles/design/templates/prototype-proof-sheet) |

## 默认复制顺序

1. 先用 [Figma Handoff 包模板](/docs/roles/design/templates/figma-handoff-pack) 或 [组件状态合同模板](/docs/roles/design/templates/component-state-contract) 锁定输入。
2. 设计系统或页面规范任务，再补 [Token 与约束模板](/docs/roles/design/templates/tokens-and-constraints)。
3. 进入走查或联调时，用 [原型验证与证据模板](/docs/roles/design/templates/prototype-proof-sheet) 收口。
