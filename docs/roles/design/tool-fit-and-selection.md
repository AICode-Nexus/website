# 工具匹配与选型

| 任务形状 | 更适合的入口 |
| --- | --- |
| 设计稿还原与组件生成 | Figma + 代码入口 |
| 原型或交互验证 | 浏览器类入口 |
| 设计系统文档化 | 长文档和结构化输出入口 |
| 与开发协作跟踪 | 平台型入口 |

## 设计任务的一个基本判断

先问自己：现在缺的是设计上下文、真实页面、规范文档，还是跨团队同步。答案不同，入口就不同。

## 典型入口组合

设计稿落地通常要同时用到 Figma 和代码入口；原型演示则更需要浏览器或可交互预览；设计系统文档化反而更适合长文档和结构化输出入口。先判定任务类型，再选入口，效率会比“哪个工具顺手用哪个”高很多。

## 常见误选

- 需要真实交互验证时，只看静态稿。
- 需要规范沉淀时，只保留口头说明。
- 需要和开发对齐时，不给真实节点、状态和限制说明。
