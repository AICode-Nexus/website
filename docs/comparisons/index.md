# 对比与选型

## 现在先做什么

- 如果你还没用过任何主工具，先去 [30 分钟上手](/docs/start/30-minute-quick-start)。
- 如果你已经知道想看哪类入口，直接去 [工具教程首页](/docs/tools)。
- 如果你已经在做真实任务，只差一条落地路径，先去 [实战案例](/docs/case-studies)。

## 这一类内容解决什么问题

对比文的任务是解决“同一层里怎么选”，不是承担整个知识结构。它适合回答：

- 同类工具之间怎么选
- 选型时该看哪些维度
- 默认入口、补位入口和观察名单怎么搭

## 当前最该看的 3 类对比

- 平台 / 控制面 / 执行栈： [GitHub Copilot、VS Code Agent 与 OpenAI Codex 怎么选](/docs/tools/compare/github-copilot-vs-vscode-agent-vs-openai-codex)
- AI IDE / 开放式入口： [Cursor、Windsurf 与 Cline 怎么看](/docs/tools/compare/cursor-vs-windsurf-vs-cline)
- 统一方法论： [AI Coding 平台比较框架](/docs/tools/compare/ai-coding-platform-comparison-framework)

## 先看什么，再看什么

1. 先确定 [AI 开发方式](/docs/development-modes)
2. 再回到这里做同层对比
3. 比完以后回到 [AI 工作流](/docs/workflows) 和 [AI 规范](/docs/standards)

## 对比时至少看 4 个维度

- 默认入口是否清晰
- 是否能接进验证、review 和 PR
- 是否支持 rules、context 与权限边界
- 是否适合团队当前任务形态

## 不要把对比文当成什么

- 不要把热度榜单当成选型结论
- 不要跨层比较，例如用 IDE 体验去比较 GitHub 工作系统
- 不要忽略长期维护成本和治理成本

## 比完以后回到哪里

- 如果你已经确定平台主入口，直接去对应 [快速开始](/docs/tools/platforms/github-copilot/quick-start) 或 [工具教程首页](/docs/tools)。
- 如果你已经确定任务形状，直接回 [AI 工作流实操手册](/docs/workflows/playbooks/workflow-playbook)。
- 如果你更想先看别人怎么落地，直接去 [实战案例](/docs/case-studies)。
