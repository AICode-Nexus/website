# 对比与选型

对比页负责解决“同一层里怎么选”，不负责替你跑通第一条主线。它最适合回答的是入口差异、控制面差异和长期治理成本，而不是把所有知识都堆成一张排行榜。

## 现在先做什么

- 如果你还没用过任何主工具，先去 [30 分钟上手](/docs/start/30-minute-quick-start)。
- 如果你已经知道想看哪类入口，直接去 [工具教程首页](/docs/tools)。
- 如果你已经在做真实任务，只差一条落地路径，先去 [实战案例](/docs/case-studies)。

## 一条正确的阅读顺序

1. 先判断你在比较的是不是同一层产品。
2. 再选一篇同层对比，而不是跨层混比。
3. 比完以后立刻回到 [工具教程](/docs/tools) 或 [工作流教程](/docs/workflows)。
4. 如果还犹豫，用 [实战案例](/docs/case-studies) 验证自己的判断。

## 对比时至少记录哪些证据

- 默认入口是什么，能不能长期承担主线任务。
- rules、memory、权限和上下文是怎么工作的。
- 能不能接验证、review、PR 和 merge。
- 成本在哪里，是模型费、治理费，还是上下文维护费。
- 失败时怎么回退，能不能顺滑切到别的入口。

## 不要把对比文当成什么

- 不要把热度榜单当成选型结论。
- 不要跨层比较，例如用 IDE 编辑体验去比较 GitHub 工作系统。
- 不要忽略长期维护成本和治理成本。
- 不要一直停留在比较阶段，不进入可执行教程或 runbook。

## 比完以后回哪里

- 如果你已经确定平台主入口，直接去对应 [GitHub Copilot 快速开始](/docs/tools/platforms/github-copilot/quick-start) 或 [工具教程首页](/docs/tools)。
- 如果你已经确定任务形状，直接回 [AI 工作流实操手册](/docs/workflows/playbooks/workflow-playbook)。
- 如果你更想先看别人怎么落地，直接去 [实战案例](/docs/case-studies)。
- 如果你发现自己其实还没跑过任何主线，直接回 [30 分钟上手](/docs/start/30-minute-quick-start)。
