# 对比与选型

## 这一类内容解决什么问题

- 哪个平台适合作为主工作流入口
- 哪些产品应该放在同一维度里比较
- 个人工程师如何用有限时间做有效试用
- 比较之后，怎样落到 7 天试用和长期固定栈

## 谁应该先读

- 正在选主平台的人
- 想做阶段性工具评估的人
- 不想被热门榜单带偏的人
- 想向团队解释“为什么先选这个”的读者

## 先记住三条规则

### 规则 1：先比层，不要先比名

GitHub Copilot、VS Code Agent、OpenAI Codex、Cursor、Windsurf、Cline 并不都在同一层。先区分：

- 平台
- 控制面
- 执行栈
- 开放式 IDE / agent 入口

### 规则 2：先比真实任务，不要先比 slogan

你要记录的是：

- 修一个真实 bug 要几轮
- review 前要补多少人工修正
- 上下文需要重讲多少次
- 长任务是否容易漂移

### 规则 3：先比较总交付成本

个人工程师真正该关心的是：

- 返工率
- review 成本
- 切换成本
- 最终 merge 时间

## 一个最小试用流程

1. 先选 2 到 3 个最常见任务
2. 用同样的验收标准比较 2 个入口
3. 只做 7 天，不做无限试用
4. 产出一页结论：主平台、备用入口、暂不投入的产品
