# Spec-First：流程与产物

## 现在先做什么

- 想按 spec 主线执行：去 [Spec-First Runbook](/docs/workflows/patterns/spec-first/runbook)。
- 想先看完整示例：去 [Spec-First 示例](/docs/workflows/patterns/spec-first/examples)。
- 想先选默认工具组合：去 [Spec-First Tooling](/docs/workflows/patterns/spec-first/tooling)。

## 最小产物清单

- 目标、非目标、验收标准和明确的边界说明。
- 需要 review 的风险、依赖和未决问题。
- spec 定稿后要交给谁执行、如何验证和何时回到 review。

## 交接时必须看见什么

- spec 不是长摘要，而是能独立指导执行和 review 的合同。
- 计划、任务拆分和执行入口要能从同一套边界推出。
- 如果边界仍在摇摆，要明确标注为待决，不要假装已经定稿。

## 最容易断裂的地方

- 写了很多背景，却没写出清晰目标和非目标。
- spec 很像文档存档，但没人把它真正拿来指导执行。
- 定稿后没有 handoff 设计，执行阶段又重新发明边界。

## 读完回哪里

- 想按主线执行：回 [Spec-First Runbook](/docs/workflows/patterns/spec-first/runbook)。
- 想看标准例子：去 [Spec-First 示例](/docs/workflows/patterns/spec-first/examples)。
- 想先选入口组合：去 [Spec-First Tooling](/docs/workflows/patterns/spec-first/tooling)。
