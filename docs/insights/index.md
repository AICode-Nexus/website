# 趋势观察

趋势页的职责不是追热点，而是把热点压缩成长期判断，帮助团队回答“哪些变化值得写进长期知识，哪些只需要当天知道”。如果你今天的核心问题是怎么动手，趋势页应该是回看层，不是起步层。

## 现在先做什么

- 先跑通可执行主线，再回来读趋势：去 [30 分钟上手](/docs/start/30-minute-quick-start)。
- 如果你要看案例化落地，去 [实战案例](/docs/case-studies)。
- 如果你已经准备收敛工具或流程，先回 [对比与选型](/docs/comparisons) 或 [工作流教程首页](/docs/workflows)。

## 先看哪一类内容

| 你的目标 | 该看什么 | 不该停留在哪里 |
| --- | --- | --- |
| 今天有什么值得知道的变化 | [Daily Brief](/blog) | 不要把日报当长期结论。 |
| 这个月最值得跟踪的主线是什么 | [2026 年 3 月月度简报](/docs/tools/insights/monthly-brief-2026-03) | 不要在单条快讯里找策略。 |
| 想先建立对 Agent 工程结构的基础认知 | [Agent = Model + Harness](/docs/tools/insights/agent-model-plus-harness) | 不要把 Agent 只理解成“更强的聊天框”。 |
| 哪些变化已经足够写进长期知识 | [2026 年 3 月 AI Coding 的四个主线变化](/docs/tools/insights/agentic-coding-patterns) | 不要把长期洞察写成当天资讯流。 |

## 趋势页到底负责什么

- 把连续出现的信号压缩成阶段性判断。
- 帮团队决定哪些变化值得回流到教程、工作流和规范。
- 让读者知道“现在最该观察什么”，而不是“今天又多了多少更新”。

## 哪些信号值得升级成长线洞察

- 已经连续出现，不再是一次性厂商热闹。
- 能改变你的入口选择、执行方式或治理要求。
- 能映射到真实工作流、review 或架构决策。
- 即使 1 到 2 周后再看，仍然有工程行动价值。

## 什么时候别再继续看趋势

- 你已经知道变化意味着什么，下一步应该回教程或 runbook 落地。
- 你读完之后仍然说不清要做什么，说明问题在执行路径，不在趋势信息量。
- 你想解决的是当前仓库里的具体任务，而不是行业方向判断。

## 推荐阅读顺序

1. 先用 [Daily Brief](/blog) 发现变化。
2. 再用月度简报判断哪些值得继续追。
3. 最后只把真正有长期价值的部分写进趋势洞察或回流到教程。

## 看完趋势后回哪条主线

- 如果趋势影响的是你的主入口选择，回到 [工具教程首页](/docs/tools)。
- 如果趋势影响的是你的交付链和 handoff，回到 [工作流教程首页](/docs/workflows)。
- 如果趋势已经能映射到真实任务，直接去 [实战案例](/docs/case-studies)。
- 如果趋势说明你根本还没形成稳定栈，回 [个人工程师栈搭建](/docs/workflows/playbooks/personal-engineer-stack-setup)。
