# AI 编程工具

## 这一类内容解决什么问题

- 用统一框架比较平台、终端 agent、AI IDE 和开放式入口
- 识别当前真正主流、值得持续追踪的工具
- 给组织建立“主入口 + 备用入口 + 观察名单”的组合
- 避免把工具热度误当成长期知识结构

## 当前主流分层

- 平台型：GitHub Copilot
- 执行栈型：OpenAI Codex
- 终端 agent：Claude Code、Gemini CLI、Cline
- AI IDE：Cursor、Windsurf、VS Code Agent
- 开放式入口：Continue、可定制 rules / MCP 工作台

## 选工具前先回答 3 个问题

1. 你的默认工作入口是在 IDE、终端，还是 GitHub 工作系统。
2. 你是否需要后台执行、并行 worktree 或异步委派能力。
3. 你更在意一体化体验，还是更在意 rules、MCP 和 provider 自定义。

如果这 3 个问题没回答清楚，工具越多，噪音通常越大。

## 推荐做法

### 第一步：选一个主入口

先确定 60% 到 80% 的日常任务由哪个入口承担。

### 第二步：选一个补位入口

例如：

- IDE 负责高频交互
- 终端负责命令驱动和验证
- GitHub / cloud agent 负责异步任务

### 第三步：建立观察名单

不是所有工具都要进入标准栈。把未定工具收进 watchlist，按月复核，比每周换栈稳得多。

## 常见误区

- 把“支持很多模型”误当成“适合团队默认入口”
- 同时长期主用三个平台
- 没有 rules 和验证门禁，就先讨论哪家模型更强
- 只看编辑体验，不看 review、PR 和工作系统集成
