# Cursor：规则、记忆与工具边界

## 现在先做什么

- 第一次厘清 IDE 规则边界：去 [Cursor 快速开始](/docs/tools/ide-first/cursor/quick-start)。
- 想把 IDE 习惯稳定下来：去 [Cursor 最佳实践](/docs/tools/ide-first/cursor/best-practices)。
- 想先把 repo 规则文件理清：去 [仓库规则文件体系](/docs/repo-instruction-files)。

## 什么时候读这页

- 你准备长期把 Cursor 当主工作台，而不是只偶尔编辑一下。
- 你要决定 repo 合同、IDE 规则和个人习惯分别放在哪。
- 你已经开始担心“入口一换，规则和上下文就断”。

## 应该写进 repo 的东西

- 目录边界、验证命令、handoff 约束和必须保留的交付证据。
- 多人协作时都要遵守的 review 要点、敏感目录和风险说明。
- 跨工具也必须成立的项目事实，不要只写在某个 IDE 入口里。

## 只留在工具里的东西

- 个人编辑偏好、短期会话上下文和局部实验提示语。
- 不值得版本化的临时提醒和一次性工作台习惯。
- 为了降低切换成本的局部记忆，但不要把它们当成唯一事实源。

## 失控信号

- 入口一换，关键规则和记忆就全部消失。
- IDE 里能看到“完成”，但仓库里找不到对应验证和 handoff 说明。
- 团队越来越依赖私有配置，公共 repo 合同却越来越薄。

## 读完回哪里

- 想先把边界定住：回 [Cursor 快速开始](/docs/tools/ide-first/cursor/quick-start)。
- 想看长期使用的稳定写法：去 [Cursor 最佳实践](/docs/tools/ide-first/cursor/best-practices)。
- 想把规则文件重新梳理：去 [仓库规则文件体系](/docs/repo-instruction-files)。
